# پلن فاز ۱، قدم ۵ — هسته کار: تسک، پروژه و «برنامه امروز»

> وضعیت: **پیشنهاد، منتظر تایید** · تاریخ: ۲۵ مهر ۱۴۰۵
> مرجع: `docs/brief.md` (اصل طراحی «کارمند در ۱۰ ثانیه بداند امروز چه کند»)، `docs/architecture.md` بخش ۲.۵ و ۵، ADR های 0002، 0005، 0007

## هدف

بعد از این قدم، یک تیم واقعاً می‌تواند کارهایش را در مدار ثبت، تقسیم و پیگیری کند. کارمند هر صبح «برنامه امروز» را می‌چیند و با تیک زدن کارها پیشرفتش را می‌بیند.

## محدوده

| داخل این قدم | بیرون از این قدم (قدم‌های بعد) |
|---|---|
| پروژه‌ها (دپارتمانی، عمومی در شرکت، یا خصوصی) و اعضای پروژه | اعلان‌ها، ساعت سکوت و به‌روزرسانی زنده (WebSocket) |
| تسک: عنوان، شرح، وضعیت، اولویت، مسئول، همکاران، سررسید شمسی، وزن، زیرتسک | پیوست فایل (به ذخیره‌ساز S3 نیاز دارد) |
| گردش کار پیش‌فرض هسته: انجام‌نشده ← در حال انجام ← انجام‌شده / لغوشده | گردش کار و انواع کار اختصاصی دپارتمان‌ها (قالب دپارتمان) |
| کامنت روی تسک | منشن (@) در کامنت |
| تاریخچه تغییرات هر تسک (چه کسی، چه چیزی را، کی عوض کرد) | XP، استریک و نشان (گیمیفیکیشن) |
| «برنامه امروز»: انتخاب کارهای امروز، پیشرفت روز، انیمیشن تکمیل کار | اسپرینت، تایید درخواست‌ها، فرم‌ها |
| صفحه «کارهای من»، نمای لیست و برد (کانبان) با کشیدن و رها کردن | جست‌وجوی سراسری، انتقال از میزیتو |
| ثبت رویدادهای دامنه (outbox) برای استفاده قدم‌های بعد | پردازش رویدادها (worker) |
| انتخابگر تاریخ شمسی در دیزاین‌سیستم | |

## ۱. مدل داده

همه جدول‌ها `tenant_id`، RLS اجباری و کلید خارجی مرکب `(tenant_id, …)` دارند، با تست جداسازی برای هر جدول.

| جدول | ستون‌های کلیدی | توضیح |
|---|---|---|
| `projects` | `department_id?`، `name`، `description`، `status` (active/archived)، `owner_id`، `visibility` (`department`/`tenant`/`private`)، `start_on`، `due_on`، `color` | |
| `project_members` | `project_id`، `member_id`، `role` (owner/member) | برای پروژه‌های خصوصی و بین‌دپارتمانی |
| `tasks` | `department_id`، `project_id?`، `parent_id?`، `title`، `description`، `type_key` (فعلاً `task`)، `status_key`، `status_category`، `priority` (low/normal/high/urgent)، `assignee_id?`، `reporter_id`، `due_on?` (تاریخ تقویمی)، `completed_at`، `weight` (۱ تا ۵)، `sort_key`، `deleted_at`، `version` | `type_key` و `status_key` از الان هست تا قالب دپارتمان بعداً بدون مایگریشن سنگین سوار شود (ADR 0004) |
| `task_collaborators` | `task_id`، `member_id`، `kind` (collaborator/watcher) | |
| `comments` | `subject_type`، `subject_id`، `author_id`، `body`، `edited_at`، `deleted_at` | عمومی؛ فعلاً فقط برای تسک |
| `activities` | `subject_type`، `subject_id`، `actor_id`، `verb`، `changes jsonb` | تاریخچه قابل‌دیدن برای کاربر (با گزارش تغییرات امنیتی فرق دارد) |
| `daily_plan_items` | `member_id`، `plan_date` (روز محلی شرکت)، `task_id`، `sort_key` | یکتا روی (عضو، روز، تسک) |
| `domain_events` | `type`، `version`، `payload`، `actor_id`، `occurred_at`، `published_at` | outbox؛ فعلاً فقط نوشته می‌شود |

**تصمیم‌ها:**
- **سررسید** به‌صورت تاریخ تقویمی (`date`) ذخیره می‌شود، نه لحظه زمانی. «امروز» و «عقب‌افتاده» با منطقه زمانی شرکت حساب می‌شود.
- **حذف تسک نرم است** (`deleted_at`) و در گزارش تغییرات امنیتی (ADR 0009) ثبت می‌شود، چون قاعده‌ی پروژه حذف را عمل حساس می‌داند. بقیه ویرایش‌ها فقط در تاریخچه تسک می‌آیند.
- **ترتیب** با کلید کسری (`sort_key`) نگه داشته می‌شود تا جابه‌جایی در برد فقط یک سطر را عوض کند.
- **کنترل هم‌زمانی:** ستون `version`. اگر دو نفر هم‌زمان یک تسک را ویرایش کنند، دومی خطای «تسک تغییر کرده» می‌گیرد و چیزی بی‌صدا بازنویسی نمی‌شود.

## ۲. دسترسی‌ها (طبق ADR 0005)

| چه کسی | چه چیزی را می‌بیند |
|---|---|
| همه | تسک‌هایی که مسئول، ثبت‌کننده یا همکارشان هستند، حتی اگر در دپارتمان دیگری باشد |
| اعضای دپارتمان | همه تسک‌های دپارتمان خودشان |
| اعضای پروژه | تسک‌های پروژه‌هایی که عضوشان هستند؛ پروژه «عمومی در شرکت» برای همه |
| دپارتمان ناظر با دسترسی «کارها» / نقش مدیریت ارشد | همه تسک‌های شرکت (فقط دیدن) |

| چه کسی | چه کاری می‌تواند بکند |
|---|---|
| عضو دپارتمان | ساخت تسک در دپارتمان خودش، واگذاری به هر عضو شرکت، تغییر وضعیت تسک‌های خودش |
| مسئول یا ثبت‌کننده | ویرایش و تغییر وضعیت تسک |
| مدیر یا سرپرست دپارتمان | ویرایش همه تسک‌های دپارتمان، **تعیین وزن** (مبنای XP آینده)، حذف |
| تسک خصوصی پروژه خصوصی | فقط اعضای همان پروژه |

همه این قوانین در API اعمال و برای هر کدام تست نوشته می‌شود.

## ۳. API

| مسیر | کار |
|---|---|
| `GET/POST/PATCH /api/projects` · `POST /api/projects/:id/archive` · `PUT /api/projects/:id/members` | پروژه‌ها |
| `GET /api/tasks?view=mine\|department\|project&…` | فهرست با فیلتر (مسئول، وضعیت، سررسید، پروژه) و صفحه‌بندی |
| `POST /api/tasks` · `GET/PATCH/DELETE /api/tasks/:id` | ساخت، دیدن، ویرایش (با `version`)، حذف نرم |
| `POST /api/tasks/:id/move` | تغییر وضعیت و جایگاه در برد |
| `PUT /api/tasks/:id/collaborators` | همکاران و دنبال‌کننده‌ها |
| `GET/POST /api/tasks/:id/comments` · `PATCH/DELETE /api/comments/:id` | کامنت (ویرایش و حذف فقط توسط نویسنده) |
| `GET /api/tasks/:id/activity` | تاریخچه |
| `GET /api/today` | برنامه امروز + پیشنهادها (سررسید امروز، عقب‌افتاده، در حال انجام) |
| `PUT /api/today/items` · `POST /api/today/items/:taskId` · `DELETE …` | چیدن برنامه امروز |

رویدادهای ثبت‌شده در outbox: `task.created`، `task.assigned`، `task.status_changed`، `task.completed`، `task.reopened`، `comment.created`، `daily_plan.updated`.

## ۴. صفحه‌ها (موبایل‌اول، راست‌به‌چپ)

| صفحه | توضیح |
|---|---|
| **امروز** (`/`) | سلام و تاریخ، نوار پیشرفت روز، فهرست «برنامه امروز» با دایره تکمیل و انیمیشن جشن، پیشنهادها («سررسید امروز»، «عقب‌افتاده») با دکمه «به امروز اضافه کن»، و افزودن سریع تسک |
| **کارها** (`/tasks`) | زبانه‌های «کارهای من» / «دپارتمان من»، فیلترها، نمای لیست (گروه‌بندی با سررسید) و نمای برد |
| **جزئیات تسک** | روی موبایل صفحه کامل، روی دسکتاپ پنل کناری: همه فیلدها، زیرتسک‌ها، کامنت‌ها، تاریخچه |
| **پروژه‌ها** (`/projects`) | فهرست پروژه‌ها با پیشرفت، صفحه هر پروژه با تسک‌هایش (لیست یا برد) |
| **دکمه افزودن سریع** | دکمه شناور روی موبایل؛ فقط عنوان کافی است، بقیه اختیاری |

**دیزاین‌سیستم:** انتخابگر تاریخ شمسی (ماه شمسی، شروع هفته از شنبه، تعطیلی جمعه، اعداد فارسی)، نشان اولویت، کارت تسک، ستون برد.

**Optimistic UI:** تیک زدن، تغییر وضعیت، جابه‌جایی در برد و افزودن به برنامه امروز بلافاصله در صفحه دیده می‌شوند و اگر سرور رد کند برمی‌گردند.

## ۵. تست‌ها

- **db:** تست جداسازی برای هر ۸ جدول جدید (تست متای موجود هم خودکار پوشش می‌دهد).
- **api:** قوانین دیدن و ویرایش (جدول بخش ۲)، دپارتمان ناظر، پروژه خصوصی، وزن فقط توسط مدیر، تعارض `version`، حذف نرم با ثبت در گزارش تغییرات، منطق «امروز» و «عقب‌افتاده» با منطقه زمانی تهران، ثبت رویدادها.
- **e2e در ۳۶۰ و ۱۴۴۰ پیکسل:**
  - کارمند تسک می‌سازد، به امروز اضافه می‌کند و تیک می‌زند؛ پیشرفت روز بالا می‌رود.
  - مدیر به کارمند کار می‌دهد؛ کارمند در «کارهای من» می‌بیندش.
  - کامنت گذاشته می‌شود.
  - کارت در برد جابه‌جا می‌شود.
  - کارمند دپارتمان دیگر آن تسک را نمی‌بیند.
- **بازبینی بصری:** همه صفحه‌ها در موبایل و دسکتاپ، روشن و تیره.
