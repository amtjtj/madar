## هدف

علی قرارداد اسکن‌شده را از گوشی، با دوربین یا از فایل‌ها، به کار «پیگیری قرارداد» پیوست می‌کند. هنگام بارگذاری نوار پیشرفت می‌بیند. مریم احمدی، که کار را می‌بیند، روی تصویر می‌زند و آن را بزرگ در همان صفحه می‌بیند. PDF را در زبانه تازه باز می‌کند و فایل Excel را دانلود می‌کند.

زیر نظرها هم می‌شود فایل گذاشت؛ مثلاً «این نسخه اصلاح‌شده است» با یک فایل Word. هر فایل فقط برای کسانی باز می‌شود که خود کار را می‌بینند. فایل‌های هر شرکت جدا نگه داشته می‌شوند و هیچ لینک دائمی یا عمومی ندارند. فایل‌ها هم مثل پایگاه داده در پشتیبان شبانه هستند.

این قدم پایه نامه (۱۲)، چت (۱۵) و صورت‌جلسه (۱۳) است، که از همین جدول و همین API استفاده می‌کنند.

| پیوست روی کار و روی نظر | پیوست نامه، پیام و صورت‌جلسه (قدم‌های ۱۲، ۱۵ و ۱۳ همین API را به کار می‌برند) |

| تنظیم سقف حجم در صفحه تنظیمات شرکت (مالک) | |

## ۱. ذخیره‌ساز (به‌روزرسانی ADR 0006)

- **رابط `FileStorage`:** `put(key, stream)`، `get(key)` (جریان داده)، `delete(key)` و `exists(key)`. دو راه‌انداز با متغیر `STORAGE_DRIVER` انتخاب می‌شوند:

| راه‌انداز | کجا | چرا |
|---|---|---|
| `local` (پیش‌فرض) | پوشه `STORAGE_DIR`؛ در تولید volume `files-data` | سرور تک‌ماشینی ADR 0016، بدون سرویس اضافه؛ همراه پشتیبان شبانه |
| `s3` | `S3_ENDPOINT`، `S3_BUCKET`، `S3_REGION`، `S3_ACCESS_KEY`، `S3_SECRET_KEY` | ذخیره‌ساز ابری ایرانی یا MinIO، وقتی فایل‌ها زیاد شوند یا چند سرور داشته باشیم |

- **کلید شیء:** همیشه سرور آن را می‌سازد: `tenants/{tenantId}/{yyyy}/{mm}/{uuid}`. نام فایل کاربر هیچ‌وقت در مسیر نمی‌آید. راه‌انداز `local` بررسی می‌کند که مسیر نهایی بیرون از `STORAGE_DIR` نرود.
- **دانلود از راه API، نه لینک امضاشده مستقیم:**
  - API هر بار دسترسی را بررسی می‌کند و فایل را جریانی می‌فرستد.
  - هم‌منشأ است، پس CSP و تنظیمات Caddy عوض نمی‌شود.
  - ذخیره‌ساز به بیرون باز نمی‌شود و آدرس امضاشده‌ای هم نشت نمی‌کند.
  - این از ADR 0006 («لینک امضاشده کوتاه‌مدت») جدا می‌شود. در ADR 0019 ثبت می‌شود و راه برگشت به لینک امضاشده برای حجم بالا باز می‌ماند.

## ۲. بارگذاری، نوع فایل و حجم

- **دو مرحله، برای همه منبع‌ها یکسان:**
  1. `POST /api/uploads` (multipart، یک فایل) فایل را جریانی ذخیره و بررسی می‌کند. یک ردیف `pending` می‌سازد که مال بارگذار است و هنوز به چیزی وصل نیست.
  2. وصل کردن: `POST /api/tasks/:id/attachments` با `{ uploadIds }`، یا ساخت نظر با `attachmentIds`. وضعیت ردیف `ready` می‌شود و منبعش ثبت می‌شود.

  نامه، چت و صورت‌جلسه بعداً فقط مرحله ۲ خودشان را اضافه می‌کنند.
- **پاک‌سازی:** بارگذاری که تا ۲۴ ساعت به چیزی وصل نشود، و پیوست حذف‌شده، با یک کار زمان‌بند در worker (روزی یک بار) از ذخیره‌ساز پاک می‌شود.
- **حجم:**
  - سقف هر فایل `tenants.settings.files.maxSizeMb` است، پیش‌فرض ۲۵ مگابایت، و مالک آن را بین ۱ تا ۱۰۰ تنظیم می‌کند.
  - API هنگام دریافت جریان داده می‌شمارد و با رسیدن به سقف قطع می‌کند (۴۱۳ `file_too_large`)، تا فایل بزرگ کامل ذخیره نشود.
  - Caddy یک سقف کلی ۱۱۰ مگابایت برای `/api/uploads` می‌گذارد.
- **فهرست سفید:** پسوند و امضای واقعی چند بایت اول فایل هر دو باید بخوانند (۴۱۵ `file_type_not_allowed`).

| گروه | پسوندها | پیش‌نمایش |
|---|---|---|
| تصویر | jpg، jpeg، png، webp، gif | بزرگ‌نمایی در صفحه |
| PDF | pdf | زبانه تازه |
| سند | docx، xlsx، pptx، doc، xls، ppt، odt، ods | دانلود |
| متن | txt، csv | دانلود |
| فشرده | zip | دانلود |
| صدا و ویدیو | mp3، m4a، mp4 | دانلود (پخش در صفحه بعداً) |

  - SVG و HTML عمداً در فهرست نیستند، چون می‌توانند اسکریپت اجرا کنند.
- **سرآیندهای دانلود:**
  - `Content-Type` از فهرست سفید می‌آید، نه از چیزی که مرورگر کاربر فرستاده.
  - `X-Content-Type-Options: nosniff` و `Content-Security-Policy: sandbox`.
  - `Content-Disposition` فقط برای تصویر و PDF `inline` است و برای بقیه `attachment`، با نام فایل UTF-8 (RFC 5987).
  - `Cache-Control: private, max-age=300`.
- **checksum:** SHA-256 هنگام دریافت حساب و ذخیره می‌شود.
- **محدودیت نرخ:** ۶۰ بارگذاری در دقیقه برای هر عضو.

## ۳. مدل داده (مایگریشن `0015_attachments`)

| ستون | توضیح |
|---|---|
| `id`، `tenant_id` | UUIDv7، RLS اجباری (`app.enable_tenant_rls('attachments')`) |
| `subject_type` | `task` / `comment` (بعداً `letter`، `message`، `minutes`)؛ تا وصل نشده `null` |
| `subject_id` | بدون کلید خارجی، چون منبع چندریختی است؛ API منبع را در همان شرکت بررسی می‌کند |
| `uploaded_by` | کلید خارجی مرکب به `members` |
| `file_name`، `extension`، `mime`، `size` (bigint)، `checksum` | `file_name` حداکثر ۲۰۰ نویسه است و تمیز می‌شود (بدون نویسه کنترلی و مسیر) |
| `object_key` | یکتا |
| `status` | `pending` / `ready` |
| `created_at`، `attached_at`، `deleted_at` | |

- **ایندکس:** `(tenant_id, subject_type, subject_id)` برای فهرست، و `(tenant_id, status, created_at)` برای پاک‌سازی.
- **تست‌ها:**
  - تست جداسازی RLS (fixture یک ردیف می‌گیرد) و meta-test کاتالوگ؛
  - تست API: شرکت دیگر پیوست را نه می‌بیند، نه دانلود می‌کند، نه وصل می‌کند؛
  - تست ذخیره‌ساز: هر کلید با شناسه همان شرکت شروع می‌شود.

## ۴. دسترسی‌ها

| کار | چه کسی |
|---|---|
| بارگذاری | هر عضو فعال (با محدودیت نرخ). فایل تا وقتی وصل نشده فقط برای خود بارگذار است |
| وصل کردن به کار | هر کس کار را می‌بیند و اجازه نظر دادن دارد، یعنی همان کسانی که نظر می‌گذارند، ناظر پروژه هم |
| وصل کردن به نظر | نویسنده نظر، هنگام ساخت نظر |
| دیدن، پیش‌نمایش و دانلود | هر کس منبع را می‌بیند: کار (`visibleTasks`)، یا نظر (یعنی کار آن نظر) |
| حذف | بارگذار، یا کسی که `canEditTask` دارد (مدیر دپارتمان، مسئول، ثبت‌کننده). حذف در AuditLog ثبت می‌شود (`attachment.deleted`) |
| سقف حجم | مالک (`tenant.manage`)، ثبت در AuditLog |

- **فقط وصل‌شده‌ها:** بارگذاری `pending` دیگران هیچ‌جا دیده یا وصل نمی‌شود. وصل کردن فقط برای بارگذاری‌های خود شخص است.

## ۵. API

| مسیر | توضیح |
|---|---|
| `POST /api/uploads` | multipart، یک فایل. برمی‌گرداند `{ id, fileName, size, mime, kind }`. خطاها: `file_too_large`، `file_type_not_allowed` |
| `POST /api/tasks/:id/attachments` | `{ uploadIds: uuid[] }` (حداکثر ۱۰). فهرست پیوست‌های کار را برمی‌گرداند. ردیف تاریخچه «… فایل … را پیوست کرد» و رویداد `attachment.added` |
| `GET /api/tasks/:id/attachments` | پیوست‌های خود کار و نظرهایش، تازه‌ترین اول |
| `POST /api/tasks/:id/comments` | فیلد تازه `attachmentIds` |
| `GET /api/attachments/:id/file` | دانلود (`attachment`). با `?inline=1` پیش‌نمایش، که فقط برای تصویر و PDF کار می‌کند |
| `DELETE /api/attachments/:id` | حذف نرم، AuditLog و رویداد `attachment.removed` |
| `GET` / `PUT /api/settings/files` | سقف حجم (همه می‌خوانند، مالک تغییر می‌دهد) |

- **قرارداد:** `attachment` شامل `id`، `fileName`، `size`، `mime`، `kind` (`image`/`pdf`/`document`/`other`)، `uploadedBy`، `createdAt`، `subject` و `can.delete` است.
- **کار و نظر:** کار `attachmentCount` می‌گیرد و هر نظر `attachments`.
- **رویدادها:** هر دو رویداد اشاره realtime `task.updated` هستند و اعلان تازه‌ای نمی‌سازند. نظر همراه فایل همان اعلان نظر را دارد.

## ۶. صفحه‌ها (موبایل‌اول، راست‌به‌چپ)

| صفحه | تغییر |
|---|---|
| **جزئیات کار** | بخش «پیوست‌ها» زیر شرح:<br>• دکمه «افزودن فایل»؛ روی گوشی منوی سیستم «دوربین، عکس‌ها، فایل‌ها» را باز می‌کند.<br>• روی دسکتاپ کشیدن و رها کردن فایل روی بخش.<br>• تصویرها در شبکه‌ای از پیش‌نمایش کوچک (همان فایل، با `object-fit`) و بقیه در فهرست، با آیکون نوع، نام، حجم به فارسی، بارگذار و زمان.<br>• هر فایل در حال بارگذاری یک نوار پیشرفت و دکمه لغو دارد.<br>• حالت خالی: «هنوز فایلی پیوست نشده». |
| **پیش‌نمایش تصویر** | پنجره تمام‌صفحه (Modal) با نام فایل، دکمه دانلود و بستن با Esc یا کشیدن به پایین روی گوشی |
| **نوشتن نظر** | دکمه سنجاق کنار «ارسال»؛ فایل‌های انتخاب‌شده به‌صورت تراشه با نوار پیشرفت و حذف؛ «ارسال» تا پایان بارگذاری غیرفعال است. پیوست‌های هر نظر زیر متن آن |
| **کارت کار** | نشان سنجاق با تعداد پیوست (اگر بیش از صفر باشد) |
| **تنظیمات شرکت** | فیلد «حداکثر حجم هر فایل (مگابایت)» در صفحه «اولویت‌بندی» یا یک صفحه کوچک «فایل‌ها» زیر منوی سازمان |
| **دیزاین‌سیستم** | کامپوننت‌های `FileTile` (فهرست)، `ImageThumb` و `UploadProgress` |

- **پیام‌های خطا** فارسی هستند:
  - «حجم فایل بیش از ۲۵ مگابایت است»؛
  - «این نوع فایل پذیرفته نمی‌شود»؛
  - «اتصال قطع شد، دوباره امتحان کنید».
- **بارگذاری** با `XMLHttpRequest` انجام می‌شود تا درصد پیشرفت را داشته باشد.

## ۷. استقرار و پشتیبان (ADR 0016)

- **`docker/compose.prod.yml`:**
  - volume `files-data` برای `api` و `worker` (`STORAGE_DIR=/data/files`)؛
  - متغیرهای `STORAGE_*` و `S3_*` در `x-app-env`، `.env.example` و `init-env.sh`.
- **`backup.sh`:**
  - کنار dump پایگاه داده یک `files-YYYYMMDD.tar.zst` از volume فایل‌ها می‌سازد (فقط با راه‌انداز `local`) و چرخش نگه‌داری‌اش مثل dump است؛
  - بررسی بازیابی (`check`) سالم بودن آرشیو را هم امتحان می‌کند.
- **`restore.sh`:** فایل‌ها را هم برمی‌گرداند.
- **`smoke.sh`:** یک بارگذاری و دانلود هم دارد.
- **Caddy:** `request_body max_size 110MB` برای `/api/uploads`.
- **`docs/deploy.md`:** بخش کوتاه «فایل‌ها کجا هستند و کی سراغ S3 برویم».

## ۸. تست‌ها

- **واحد (shared و api):**
  - فهرست سفید و تشخیص امضا (JPEG، PNG، PDF، ZIP و اسناد Office)؛
  - تمیز کردن نام فایل؛
  - ساخت کلید با پیشوند شرکت؛
  - امنیت مسیر در راه‌انداز `local` (`../`)؛
  - شمارنده حجم که قطع می‌کند؛
  - سرآیند `Content-Disposition` فارسی.
- **یکپارچه (API، با راه‌انداز `local` در پوشه موقت):**
  - بارگذاری و وصل کردن به کار و نظر؛ دانلود با سرآیندهای درست؛
  - ۴۱۳ و ۴۱۵ (پسوند درست ولی محتوای HTML)؛
  - کسی که کار را نمی‌بیند: ۴۰۴؛
  - وصل کردن بارگذاری کس دیگر: ۴۰۴؛
  - حذف و AuditLog؛ پاک‌سازی بارگذاری رهاشده؛
  - **شرکت دیگر:** دانلود، وصل کردن و حذف همه ۴۰۴.
- **راه‌انداز `s3`:** تست قرارداد همان رابط، فقط اگر `S3_ENDPOINT` تنظیم باشد (در CI با MinIO، وگرنه skip).
- **پایگاه داده:** RLS و fixture.
- **e2e (۳۶۰ و ۱۴۴۰):**
  - پیوست تصویر و PDF به کار، دیدن در فهرست، پیش‌نمایش تصویر و دانلود PDF؛
  - نظر با فایل؛
  - خطای فایل بزرگ و نوع غیرمجاز؛
  - حذف؛
  - کسی از دپارتمان دیگر به آدرس دانلود دسترسی ندارد.
- **تولید:** `smoke.sh` روی پشته تولید محلی، و یک تمرین بازیابی با فایل.
- **بررسی چشمی:** بخش پیوست‌ها، پیش‌نمایش و نوشتن نظر در هر دو عرض و هر دو پوسته.

## ۹. ترتیب کار (هر مرحله یک commit سبز)

1. **shared:** قرارداد پیوست، فهرست سفید و تشخیص امضا، تمیز کردن نام، تنظیمات فایل، کدهای خطا، رشته‌ها؛ با تست.
2. **db:** مایگریشن `0015` (جدول، RLS، ایندکس‌ها) و تست جداسازی.
3. **API، ذخیره‌ساز:** رابط `FileStorage` با راه‌اندازهای `local` و `s3`، پیکربندی env، تست‌ها.
4. **API، پیوست‌ها:** بارگذاری جریانی (شمارنده حجم، امضا، checksum)، وصل به کار و نظر، فهرست، دانلود و پیش‌نمایش، حذف با AuditLog، تنظیم سقف، محدودیت نرخ، رویدادها و realtime؛ تست‌ها.
5. **worker:** پاک‌سازی روزانه بارگذاری‌های رهاشده و فایل‌های حذف‌شده؛ تست.
6. **UI و وب:** کامپوننت‌های دیزاین‌سیستم، بخش پیوست‌ها، پیش‌نمایش، پیوست نظر، نشان روی کارت، فیلد تنظیمات.
7. **استقرار:** volume، env، Caddy، پشتیبان، بازیابی، smoke، `docs/deploy.md`.
8. **پایان:** seed (چند فایل نمونه کوچک ساخته‌شده در خود اسکریپت: یک PNG و یک PDF)، e2e، ADR 0019، یادداشت‌های `CLAUDE.md`، `pnpm check`، e2e کامل، بررسی چشمی، بازبینی مستقل، پوش.

> اگر مرحله ۷ (پشتیبان و بازیابی) طولانی شد، آن را به قدم ۱۱ب جدا می‌کنم و اینجا می‌گویم. پیش‌فرض این است که در همین قدم بماند، چون بدون آن فایل‌ها پشتیبان ندارند.

| سقف حجم | ۲۵ مگابایت پیش‌فرض، قابل تنظیم برای مالک بین ۱ تا ۱۰۰ |
| نوع فایل | فهرست سفید بالا، با بررسی امضای واقعی؛ SVG و HTML نه |
| دسترسی | هر کس منبع را می‌بیند، فایل را هم می‌بیند. ناظر پروژه هم می‌تواند فایل بگذارد، مثل نظر |
| حذف | حذف نرم با AuditLog؛ پاک شدن واقعی از ذخیره‌ساز در پاک‌سازی روزانه |
| پیش‌نمایش | تصویر در صفحه، PDF در زبانه تازه، بقیه دانلود؛ بدون ساختن تصویر کوچک در سرور |

## سوال‌ها برای مالک محصول

1. **سقف حجم:** ۲۵ مگابایت برای هر فایل مناسب است؟ ویدیو هم لازم است؟ ویدیو معمولاً سقف بالاتری می‌خواهد.
2. **فهرست نوع فایل:** فایل‌های دیگری هم لازم است، مثلاً `rar` یا فایل‌های طراحی؟ (پیشنهاد من: فعلاً همین فهرست.)
3. **اسکن ویروس:** با ClamAV روی همان سرور ممکن است، ولی حدود ۱ گیگابایت حافظه می‌خواهد. پیشنهاد من: بعداً، وقتی سرور بزرگ‌تر شد. تا آن موقع فهرست سفید و بررسی امضا هست.
4. **محل فایل در تولید:** دیسک همان سرور کافی است، یا از اول ذخیره‌ساز ابری (مثلاً آروان) می‌خواهید؟ (پیشنهاد من: دیسک سرور، چون ساده‌تر و ارزان‌تر است و در پشتیبان هست.)
