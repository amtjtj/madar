# فرض‌های شرکت پایلوت (تا گرفتن اطلاعات واقعی)

> وضعیت: **فرض، تایید نشده** · تاریخ: ۲۵ مهر ۱۴۰۵
>
> این فرض‌ها جای اطلاعاتی را می‌گیرند که هنوز از شرکت طلا نگرفته‌ایم. همه‌جا به‌صورت **تنظیمات شرکت یا داده seed** پیاده می‌شوند، نه کد ثابت؛ پس اگر واقعیت فرق داشت فقط تنظیم یا seed عوض می‌شود.
> وقتی هر مورد تایید یا رد شد، همین‌جا به‌روزش کنید.

## ۱. خروجی میزیتو

**فرض:** میزیتو API عمومی ندارد و ادمین فقط می‌تواند از UI خروجی Excel بگیرد، به تفکیک پروژه.

ستون‌هایی که انتظار داریم در هر ردیف تسک باشد:

| ستون فرضی | نگاشت در مدار |
|---|---|
| عنوان | `tasks.title` |
| شرح | `tasks.description` |
| پروژه | `projects.name` |
| مسئول(ها) | اولی `assignee_id`، بقیه `task_collaborators` |
| ایجادکننده | `reporter_id` |
| وضعیت (انجام نشده / در حال انجام / انجام شده) | `status_key` با نگاشت دستی ادمین |
| اولویت | `priority` |
| تاریخ شروع و سررسید (شمسی، مثل `1405/07/25`) | `start_at`, `due_at` (تبدیل به UTC) |
| تاریخ ایجاد و انجام | `created_at`, `completed_at` |
| برچسب‌ها | فیلد select |

**پیامد طراحی:** آداپتور `MizitoExcelAdapter` باید با نام ستون‌های فارسی و ترتیب متغیر کنار بیاید (تطبیق ستون با UI)، تاریخ شمسی را با و بدون ساعت بخواند، و کاربران را با **نام نمایشی** تطبیق دهد، چون احتمالاً ایمیل و موبایل در خروجی نیست. کامنت‌ها و پیوست‌ها احتمالاً در Excel نیستند و ممکن است منتقل نشوند.

**راستی‌آزمایی:** با اولین فایل نمونه واقعی، این جدول اصلاح می‌شود.

## ۲. روزها و ساعت کاری

**فرض برای شرکت پایلوت** (استارتاپ فین‌تک در تهران):

| مورد | مقدار |
|---|---|
| روزهای کاری | شنبه تا چهارشنبه |
| پنجشنبه | تعطیل (پیش‌فرض محصول «نیمه‌وقت» می‌ماند، ولی seed شرکت پایلوت پنجشنبه را تعطیل می‌گذارد) |
| جمعه | تعطیل |
| ساعت کاری | ۹:۰۰ تا ۱۸:۰۰ |
| ساعت سکوت اعلان | ۱۸:۰۰ تا ۹:۰۰ و کل روزهای تعطیل |
| منطقه زمانی | `Asia/Tehran` |
| تعطیلات رسمی | تقویم رسمی ایران برای ۱۴۰۵ و ۱۴۰۶ |

## ۳. چه کسی چه چیزی را می‌بیند (در میزیتو)

**فرض:** میزیتو پروژه‌محور است: هر کس پروژه‌هایی را می‌بیند که عضوشان است، مدیران پروژه‌های تیم خود را می‌بینند و مدیرعامل همه را.

**پیامد:** این با مدل ما (ADR 0005) سازگار است. هنگام انتقال:
- اعضای هر پروژه میزیتو ← `project_members`.
- پروژه‌ای که اعضایش از چند دپارتمان‌اند ← `visibility = department` در دپارتمان مالک + عضویت پروژه برای بقیه، تا کسی دسترسی‌ای را که در میزیتو داشته از دست ندهد و دسترسی اضافه هم نگیرد.

## ۴. ساختار شرکت برای seed

**فرض:** حدود ۲۰۰ نفر. seed قدم ۴ یک نسخه کوچک (۵ دپارتمان، ۲۰ نفر) می‌سازد:

| دپارتمان | قالب | نفرات در seed | ناظر؟ |
|---|---|---|---|
| مدیریت ارشد | مدیریت ارشد | ۲ (مدیرعامل، مدیر عملیات) | بله: کار، پروژه، هدف، شاخص، تایید |
| فنی | فنی | ۷ | خیر |
| مارکتینگ | مارکتینگ | ۴ | خیر |
| پشتیبانی | پشتیبانی | ۴ | خیر |
| منابع انسانی | منابع انسانی (سبک) | ۳ | بله: پرسنل، مرخصی، چارت |

## ۵. ورود کارکنان

**فرض:** کارکنان ایمیل سازمانی ندارند یا از آن استفاده نمی‌کنند و همه موبایل دارند. پس ورود با نام کاربری و رمز (ADR 0003) برای MVP درست است و ستون `phone` برای ورود پیامکی بعدی از الان پر می‌شود (در seed و فرم ساخت حساب، اختیاری).

## سوال‌هایی که هنوز باید از شرکت پرسید

1. یک خروجی واقعی از میزیتو (حتی یک پروژه کوچک).
2. پنجشنبه تعطیل است یا نیمه‌وقت؟ ساعت کاری دقیق؟
3. آیا در میزیتو کسی هست که همه پروژه‌ها را ببیند غیر از مدیرعامل؟
