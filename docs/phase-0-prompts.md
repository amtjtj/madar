# مدار — پرامپت‌های فاز صفر و شروع فاز یک

هر پرامپت را جدا به Claude Code بدهید. تا قدم قبلی تمام و تست نشده، سراغ قدم بعد نروید.

---

## قدم ۰ — آماده‌سازی (کار خودتان، بدون پرامپت)

1. یک پوشه خالی به اسم `madar` بسازید و داخلش `git init` بزنید.
2. فایل `CLAUDE.md` را در ریشه پوشه بگذارید.
3. بریف را از داکیومنت با فرمت Markdown خروجی بگیرید و در `docs/brief.md` ذخیره کنید.
4. داخل پوشه، Claude Code را باز کنید و این دو MCP را اضافه کنید:

```bash
claude mcp add context7 -- npx -y @upstash/context7-mcp
claude mcp add playwright -- npx -y @playwright/mcp@latest
```

5. پلاگین طراحی رسمی Anthropic را داخل Claude Code نصب کنید:

```
/plugin marketplace add anthropics/claude-code
/plugin install frontend-design@claude-code-plugins
```

> اگر دستوری خطا داد، متن خطا را برای من بفرستید تا دستور درست را پیدا کنیم.

## قدم ۱ — طراحی معماری (فقط پلن، بدون کد)

قبل از این پرامپت، با `Shift+Tab` وارد Plan Mode شوید.

```
CLAUDE.md و docs/brief.md را کامل بخوان.

هنوز هیچ کدی ننویس. یک سند معماری در docs/architecture.md پیشنهاد بده که این‌ها را پوشش بدهد:

1. ساختار نهایی monorepo و مسئولیت هر پکیج
2. مدل داده هسته: جدول‌ها، رابطه‌ها، و اینکه RLS برای جداسازی شرکت‌ها دقیقاً چطور پیاده می‌شود
3. طراحی «قالب دپارتمان»: یک ماژول دپارتمانی چطور با کانفیگ (نوع تسک، وضعیت‌ها، فرم‌ها، گردش تایید، شاخص‌ها، چیدمان داشبورد) تعریف می‌شود، و ماژول‌های آماده (پشتیبانی، مارکتینگ، فنی، مدیریت ارشد) چطور روی آن سوارند
4. مدل نقش و دسترسی (سازمان، دپارتمان، فرد)
5. رویدادهای دامنه بین ماژول‌ها (مثلاً تیکت پشتیبانی که به باگ فنی تبدیل می‌شود)
6. ساختار داده گیمیفیکیشن (XP، استریک، نشان، قدردانی)
7. نقشه انتقال اطلاعات از میزیتو (فقط طراحی کلی)
8. ریسک‌های فنی و جاهایی که هنوز تصمیم لازم است

هر جا بین دو گزینه مردد بودی، هر دو را با مزیت و عیب بنویس و یکی را پیشنهاد بده.
```

**بعد از جواب:** سند را برای من بفرستید تا قبل از تایید با هم بررسی‌اش کنیم.

## قدم ۲ — ساخت اسکلت پروژه

```
طبق docs/architecture.md که تایید شد، اسکلت monorepo را بساز:

- Turborepo + pnpm با apps/web (Next.js) و apps/api (NestJS) و پکیج‌های db، shared، ui، i18n
- TypeScript strict، ESLint و Prettier مشترک
- docker-compose برای PostgreSQL و Redis در محیط توسعه
- Vitest برای تست واحد و Playwright برای تست e2e، هرکدام با یک تست نمونه که پاس شود
- فایل .env.example با همه متغیرها و .gitignore درست
- یک صفحه ساده در web که از api داده بگیرد تا اتصال دو طرف ثابت شود

در پایان:
1. بخش Commands در CLAUDE.md را با دستورهای واقعی پر کن
2. نسخه دقیق کتابخانه‌ها را در docs/decisions/0001-stack.md ثبت کن
3. همه دستورهای typecheck، lint و test را اجرا کن و نشان بده که سبز هستند
```

## قدم ۳ — پایه‌های دیزاین‌سیستم

```
با کمک skill طراحی (frontend-design)، پایه دیزاین‌سیستم مدار را در packages/ui بساز. حس کلی: روان، زنده و دوست‌داشتنی مثل Duolingo، ولی جدی و قابل اعتماد برای مدیرعامل یک شرکت مالی. از ظاهر قالب‌های تکراری پرهیز کن.

- توکن‌های رنگ، فاصله، گوشه، سایه و تایپوگرافی؛ تم روشن و تیره
- فونت Vazirmatn به‌صورت self-hosted
- RTL کامل با کلاس‌های منطقی Tailwind
- ابزار تاریخ شمسی و تبدیل اعداد به فارسی
- کامپوننت‌های پایه: دکمه، ورودی، کارت، نوار پیشرفت، آواتار، نشان، اسکلتون، حالت خالی، توست، مودال، ناوبری پایین موبایل و سایدبار دسکتاپ
- یک انیمیشن «تکمیل کار» کوتاه و رضایت‌بخش
- یک صفحه /design-system که همه کامپوننت‌ها را در هر دو تم نشان بدهد

در پایان با Playwright از صفحه در عرض ۳۶۰ و ۱۴۴۰ پیکسل، در هر دو تم، اسکرین‌شات بگیر و مشکلات چیدمان را رفع کن.
```

## قدم ۴ — شروع فاز یک: ورود، شرکت و ساختار سازمانی

```
اولین فیچر هسته را پیاده کن. اول پلن بده و منتظر تایید بمان.

- ثبت‌نام شرکت جدید (Tenant) و اولین ادمین
- ورود با Better Auth با نام کاربری و رمز (ADR 0003)، تغییر رمز اجباری در ورود اول، و ورود دومرحله‌ای TOTP برای ادمین‌ها
- تعریف دپارتمان‌ها و چارت سازمانی، با تنظیم «دپارتمان ناظر» (ADR 0005)
- ساخت حساب اعضا توسط ادمین (نام کاربری و رمز اولیه) و تعیین نقش و دپارتمان
- سیاست‌های RLS برای همه جدول‌های جدید، همراه تستی که ثابت کند شرکت الف داده شرکت ب را نمی‌بیند
- ثبت در AuditLog برای تغییر نقش و دسترسی
- داده نمونه (seed): یک شرکت فرضی طلای آنلاین با ۵ دپارتمان و ۲۰ کارمند فارسی‌نام

طبق Workflow در CLAUDE.md تا آخر برو و در پایان بگو چه چیزی را دستی تست کنم.
```

## نکته‌های کار با Claude Code

- **هر قدم را در یک گفت‌وگوی تازه شروع کنید** (`/clear`). فایل CLAUDE.md خودش زمینه را می‌دهد و گفت‌وگوی شلوغ کیفیت را پایین می‌آورد.
- **قبل از هر قدم بزرگ commit بزنید** تا اگر خراب شد راحت برگردید.
- اگر Claude Code چیزی را حدس زد یا از مسیر خارج شد، متوقفش کنید (`Esc`) و دقیق‌تر بگویید.
- خروجی هر قدم یا هر جا گیر کردید را برای من بفرستید تا پرامپت بعدی را دقیق‌تر بنویسیم.
