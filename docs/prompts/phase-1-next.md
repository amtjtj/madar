# مدار — ادامه فاز یک: تا دموی هسته برای شرکت طلا

وضعیت در ۲۶ مهر ۱۴۰۵: قدم‌های ۰ تا ۵ تمام شده‌اند (اسکلت، دیزاین‌سیستم، ورود و ساختار سازمانی، تسک و پروژه و «برنامه امروز»).
برای رسیدن به «دروازه» فاز یک (دموی هسته به شرکت طلا) چهار قدم مانده است.

## روال هر قدم (از این به بعد)

```
/clear
/plan-step <شماره و هدف قدم>
   ← پلن را بخوانید (یا برای من بفرستید)، اصلاح یا تایید کنید
تایید است، طبق پلن پیاده کن.
   ← پیاده‌سازی، commit به commit
/finish-step
   ← بررسی مستقل، اسکرین‌شات، گزارش فارسی و چک‌لیست تست دستی
```

متن‌های زیر را جلوی `/plan-step` بگذارید. هرچه بعد از آن بنویسید، به‌عنوان «هدف قدم» به Claude Code می‌رسد.

## قدم الف — خانه‌تکانی (یک‌بار، قبل از قدم ۶)

این را مستقیم بدهید، بدون `/plan-step`:

```
قبل از قدم بعد، چند کار نگهداری:

1. پوشه .claude/agents و .claude/commands که اضافه کردم را بخوان و اگر با ساختار و دستورهای واقعی پروژه نمی‌خوانند، اصلاحشان کن.
2. CLAUDE.md ریشه بلند شده است. قاعده‌هایی را که فقط به یک بخش مربوط‌اند به CLAUDE.md های تودرتو منتقل کن: apps/web/CLAUDE.md (قاعده‌های UI، فونت، اعداد، 'use client') و apps/api/CLAUDE.md (withTenant، access.ts، کد خطا، audit، SYSTEM_ROLE_GRANTS). در ریشه فقط قاعده‌های طلایی، استک، ساختار، روال کار و دستورها بماند. هیچ قاعده‌ای حذف نشود.
3. در یک بازبینی، تست work.test.ts در apps/api یک بار وقتی همه تست‌های monorepo هم‌زمان روی یک دیتابیس اجرا شدند شکست خورد (خطای Better Auth روی جدول sessions) و بار بعد پاس شد. علت را پیدا کن (احتمالاً تست‌های db و api هم‌زمان داده مشترک را عوض می‌کنند) و طوری درستش کن که تست‌ها مستقل از ترتیب و هم‌زمانی پاس شوند.
4. docs/phase-0-prompts.md را به docs/prompts/phase-0.md منتقل کن و فایل docs/prompts/phase-1-next.md را کنارش نگه دار.

هر کار یک commit جدا.
```

## قدم ۶ — موتور پس‌زمینه، اعلان‌ها، به‌روزرسانی زنده و اپ نصب‌شدنی

چرا الان: گیمیفیکیشن، تاییدها و گزارش هوشمند همه به worker و رویدادها نیاز دارند. outbox از قدم ۵ آماده است ولی هنوز کسی آن را پردازش نمی‌کند.

```
/plan-step 6 — worker و اعلان‌ها و به‌روزرسانی زنده و PWA

- راه‌اندازی worker (entrypoint دوم در apps/api طبق ADR 0006): relay برای outbox با FOR UPDATE SKIP LOCKED، صف BullMQ، مصرف‌کننده‌های idempotent با processed_events
- اعلان درون‌برنامه: واگذاری تسک به من، کامنت روی تسک من، نزدیک شدن یا گذشتن سررسید، اضافه شدن به پروژه
- مرکز اعلان (زنگوله با شمارنده، خواندن و خواندن همه) و تنظیمات اعلان هر نفر
- ساعت سکوت طبق ساعت و روزهای کاری شرکت (pilot-assumptions): اعلان ساخته می‌شود ولی push خارج از ساعت کاری فرستاده نمی‌شود
- به‌روزرسانی زنده با WebSocket: تغییر تسک، برد و اعلان بدون رفرش؛ اتاق‌ها به شرکت و دسترسی محدود باشند
- PWA: manifest، آیکون‌ها، صفحه آفلاین، قابل نصب روی اندروید و iOS؛ Web Push با کلید VAPID روی سرور خودمان (بدون سرویس خارجی)
- تست: هیچ اعلان یا پیام WebSocket به شرکت یا کاربر دیگر نرسد
```

## قدم ۷ — هدف‌گذاری (OKR) سه‌سطحی

```
/plan-step 7 — هدف‌گذاری OKR سه‌سطحی

- دوره‌ها (فصلی، با تقویم شمسی) و هدف در سه سطح: سازمان، دپارتمان، فرد؛ هر هدف می‌تواند زیرمجموعه هدف بالاتر باشد
- نتیجه کلیدی با سه نوع: عددی (از، تا، فعلی)، درصدی، و انجام‌شد/نشد؛ و امکان وصل کردن تسک‌ها و پروژه‌ها به نتیجه کلیدی
- ثبت پیشرفت (check-in) با یادداشت و وضعیت «در مسیر / در خطر / عقب»، و تاریخچه آن
- محاسبه خودکار پیشرفت هدف از نتیجه‌های کلیدی و از هدف‌های زیرمجموعه
- صفحه‌ها: درخت اهداف شرکت، اهداف دپارتمان من، اهداف من؛ ساخت هدف در کمتر از یک دقیقه روی موبایل
- دسترسی طبق ADR 0005 (دپارتمان‌های ناظر کل شرکت را می‌بینند)
- رویدادهای outbox برای check-in و تکمیل هدف (برای گیمیفیکیشن قدم‌های بعد)
- seed: اهداف فصل جاری برای «زرین‌مدار» در سه سطح
```

## قدم ۸ — خانه هر نقش و داشبورد مدیران

```
/plan-step 8 — خانه هر نقش و داشبورد مدیرعامل و مدیر دپارتمان

اصل طراحی بریف: کارمند در ۱۰ ثانیه بداند امروز چه کند؛ مدیرعامل در ۳۰ ثانیه وضعیت کل شرکت را بفهمد.

- خانه مدیرعامل: پیشرفت اهداف شرکت، دپارتمان‌هایی که عقب‌اند، کارهای گذشته از سررسید به تفکیک دپارتمان، پروژه‌های در خطر، روند هفتگی کارهای انجام‌شده
- خانه مدیر دپارتمان: بار کاری تیم، کارهای گیرکرده، اهداف دپارتمان، چه کسی کمک لازم دارد (بدون رتبه‌بندی افراد)
- خانه کارمند: همان «امروز» به‌علاوه خلاصه هدف‌های من
- هر کارت داشبورد با یک کلیک به لیست فیلترشده همان داده برود
- گزارش هفتگی ساده (بدون AI) برای هر دپارتمان و کل شرکت، قابل خروجی PDF
- نمودارها با یک کتابخانه سبک و self-hosted، فارسی، راست‌به‌چپ، با تم روشن و تیره
- عملکرد: باز شدن خانه زیر ۲ ثانیه با داده seed؛ کوئری‌های تجمیعی با ایندکس مناسب
```

## قدم ۹ — استقرار آزمایشی و آماده‌سازی دمو

این را مستقیم بدهید (پلن آن فنی‌تر است):

```
می‌خواهیم مدار را روی یک سرور ابری ایرانی بالا بیاوریم تا شرکت پایلوت دمو را روی گوشی خودش ببیند. اول پلن بده و منتظر تایید بمان.

- Dockerfile تولیدی برای web و api و worker، و docker-compose تولیدی با Postgres، Redis و reverse proxy با HTTPS
- مایگریشن خودکار هنگام استقرار، پشتیبان‌گیری روزانه از دیتابیس و تست بازگردانی آن
- متغیرهای محیطی و رازها خارج از git؛ راهنمای استقرار در docs/deploy.md برای کسی که اولین بار سرور راه می‌اندازد
- لاگ و مانیتورینگ ساده (سلامت سرویس‌ها، خطاها) بدون سرویس خارجی
- یک «حالت دمو»: شرکت «زرین‌مدار» با داده واقعی‌نما و حساب‌هایی برای مدیرعامل، مدیر دپارتمان و کارمند
- اسکریپت دمو در docs/demo-script.md: ۱۰ دقیقه، از دید سه نقش، با جمله‌هایی که در جلسه گفته می‌شود
```
